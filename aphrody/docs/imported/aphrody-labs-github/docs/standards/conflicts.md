# Conflicts between sources

Where two or more sources disagree, this file records the decision and why. Rule IDs refer to [code-style.md](code-style.md); source tags are defined there and in [sources.toml](sources.toml). General order of decision: a forked or vendored tree keeps its upstream's own rule; for Bun-run code the output of `bun fmt` and `bun lint` wins; otherwise the stricter safety rule wins; otherwise the estate's existing standard stays.

| ID | Topic | What the sources say | Decision | Why |
| :-- | :-- | :-- | :-- | :-- |
| C-01 | Quotes in TS and JS | GTS and GJS require single quotes. `bun fmt` prints double quotes by default (Prettier output) and the Bun tree sets no `singleQuote`. | Double quotes. | `bun fmt` is native and mandatory; a rule the formatter would undo cannot be enforced. |
| C-02 | Line width of TS and JS | GJS says 80 columns. GTS names no limit. The Bun formatter defaults to 80; the Bun tree's own `.prettierrc` sets 120; the Rust style guide sets 100. | `printWidth = 100` in `[fmt]`. | One width for TypeScript and Rust in the estate; `bun fmt` supports the option natively. The Bun tree keeps its own 120. |
| C-03 | `#private` fields | GTS forbids them (emit size and speed after downleveling). BUN API design recommends private symbols or `#fields` over underscore names. | Allowed in Bun-run code. | Bun runs the source natively without downleveling, which removes the cost GTS cites; Bun's rule wins for Bun-run code. |
| C-04 | Default exports | GTS forbids them. Bun.serve reads `export default { fetch }`; tool config files (`*.config.ts`) require them. | Named exports by default; `import/no-default-export` warns, with an override for `*.config.*`. | The runtime contract overrides the style preference where the runtime reads the default export. |
| C-05 | `@ts-expect-error` | GTS bans `@ts-ignore`, `@ts-expect-error` and `@ts-nocheck`, with a tests-only exception. The Bun linter's recommended setup allows `@ts-expect-error` with a description. | `@ts-ignore` and `@ts-nocheck` banned; `@ts-expect-error` allowed with a description. | The linter's output wins; an expected error fails when the error disappears, so it cannot rot like `@ts-ignore`. |
| C-06 | `require()` in TS | GTS bans the `import x = require()` form and `require` for imports. Bun's linter allows `require()` in TypeScript by default because Bun runs `import` and `require` in one file. | Allowed where Bun allows it; the `import x = require()` syntax stays banned. | Bun's default wins for Bun-run code; the banned form is a TypeScript-compiler construct we do not use. |
| C-07 | Rust import layout | RFL: vertical, one item per line, trailing `//`. GRS: one module per `use` (`imports_granularity = "Module"`, nightly rustfmt). RSG and rustfmt default: condensed nested imports. | Default for userland; vertical for kernel-facing; Module granularity for browser-facing where nightly rustfmt is pinned. | Each profile keeps the layout of the project it mirrors, so patches move between them without churn; the default is the community-consistent baseline. |
| C-08 | rustfmt overrides | CRS sets `use_small_heuristics = "Max"`, `wrap_comments`, `style_edition = "2021"`. RFL uses the rustfmt defaults. RSG recommends the defaults. | Defaults plus stable `edition`, `style_edition`, `newline_style`, `hex_literal_case`. | The Rust style guide says the largest benefit comes from default settings; two of three sources use them; Chromium's own file calls its heuristics choice revisitable. |
| C-09 | Lint severity | Bun's workspace sets rustc `warnings` to deny and many clippy lints to deny. RFL and CCL use warnings and treat `-D warnings` as a CI concern; CCL calls its policy relaxed. | `warn` in Cargo.toml, `-D warnings` in CI. The Bun tree keeps its own denies. | The same lints block merging either way, and local edits stay quick; code that is not Bun's tree does not inherit a build that fails on a warning. |
| C-10 | `unwrap` | GRS prefers `expect` over `unwrap`. BUN says reachable failures are errors, never panics. CCL leaves such choices to engineers. | `clippy::unwrap_used` warns; tests are exempt through `clippy.toml`. | Satisfies both GRS and BUN at a cost one lint carries; panics for invariants remain through `expect`. |
| C-11 | Rust test framework | CRS: GN `gtest` integration, no `#[cfg(test)]`. RFL: doctests as KUnit, `#[test]` and kselftests. | `cargo test`, doctests as usage examples. | gtest integration exists only inside the Chromium build; outside it the standard tooling applies. |
| C-12 | `async` and threads | GRS bans `async`/`.await` and `std::thread` in Chromium code. The estate runs Rust servers and tooling on tokio and Bun's thread pool. | Rejected for the estate; kept inside code that runs in a browser's own task system. | The ban follows from Chromium's threading and task model, which our userland code does not share. |
| C-13 | Crate layout | GRS and CRS: small crates, flat file layout, no subdirectories per crate (GN build). Cargo convention and the Rust style guide use `src/` and nested modules. | Small crates and leaf-module naming kept; the flat file layout is not used. | GRS itself exempts Cargo-built third-party code from the flat layout; our crates build with Cargo. |
| C-14 | Unstable features | GRS, CUN and RFM: stable only unless approved. The Bun tree pins a nightly and uses `-Zbuild-std` and nightly rustfmt keys; the kernel builds with nightly flags. | Stable by default; a repository that pins a nightly may use unstable features, each with a comment naming the tracking issue. | Matches both: policy for new code, reality for trees that need nightly. |
| C-15 | Commit subject shape | Bun: `area: summary` (46 of 100 measured titles carry an area prefix; only 4 use a conventional type). Rust for Linux: `subsystem: summary`. Google: a plain imperative sentence. The estate's own history already reads `area: sentence`. The previous standard text: Conventional Commits `type(scope): subject`. | Default `area: summary`; `type(scope): summary` stays accepted (`--style=conventional`). Decision of 2026-11-17, from the owner's standing instruction to follow Bun's commit and PR style. | Three of the five sources and the estate's practice use the area form; the type form remains for repositories that generate release notes from commit types. |
| C-16 | Subject length | The standard: 72. Measured Bun median: 75 characters, 52 of 100 above 72. GEP: short and focused. | 72, not counting the `(#N)` suffix GitHub appends. | History listings truncate near 72; Bun's long titles are a measured habit, not a rule in any of its documents. |
| C-17 | AI and tool attribution | Owner and STANDARD: no attribution trailers. KAI: disclose tools in the changelog. MEAS: 2 squash commits carry `Co-authored-by` for an assistant and 2 pull request bodies end with a generated-by footer. | No trailers or footers on new commits; existing history on shared branches is not rewritten (20 of the last 100 commits of the Bun fork carry an assistant `Co-authored-by`). The verification section says what was run, which is the information KAI wants from disclosure. Material tool use may be described in prose in the body. | Attribution trailers add no information a reviewer can act on; how it was verified does. Submissions to an upstream follow that upstream's rule, with the owner's decision. |
| C-18 | Signed-off-by | KPS: sign-off certifies the DCO on every patch. KAI: an agent must not add it. STANDARD: only when the README asks for a DCO. MEAS: 0 of 100 squash commits carry it. | Only when the README asks, only a human's. | Consistent across the three; an agent cannot certify origin. |
| C-19 | Body wrapping | KPS: 75 columns. The estate squashes with the pull request body as the message (Markdown, tables). | 72 for direct commits; Markdown squash bodies are not wrapped. | Wrapping Markdown tables breaks them; terminals read 72-column commit bodies well. |
| C-20 | Change size | GEP: about 100 lines comfortable, 1000 usually too large. MEAS: median 1947 changed lines, 60 of 100 above 1000. | GEP's numbers. | The measured window is dominated by consolidations and a compiler rewrite; Bun's own review guide still says diff size alone justifies changes-requested. |
| C-21 | Approval bar | GEP: approve once the change improves code health. BUN: green CI on every platform and a test are hard preconditions, and a reviewer may request changes on CI alone. | Both: the bar is GEP's, the preconditions are BUN's. | They do not contradict: preconditions decide whether the change is reviewable, GEP decides whether it is good enough. |
| C-22 | Doc comments on private items | RFL: use `///` even on private items. BUN: only comment what code cannot say. GRS: omit documentation that repeats the name. | Comment sparingly; when a private item is documented, use `///`. | Keeps RFL's tooling benefit without BUN's and GRS's noise. |
| C-23 | Comment punctuation | RFL and RSG: complete sentences, capital, period. BUN: one line, no prose. | Rust comments follow RSG and RFL; TypeScript comments are short and unpunctuated unless they are sentences. | Each rule matches the language's tooling (rustdoc renders Markdown; JSDoc does not require sentences). |
| C-24 | Safety scrutiny | CUN: unsafe needs no extra approval, only careful owner review. BUN: SAFETY comments required and accurate. RFL: SAFETY comment before every unsafe block. | Comment mandatory for all; second reviewer for unsafe and FFI (RV-08). | Strictest of the three where it costs a comment, not a process. |
| C-25 | `allow` versus `expect` | RFL: prefer `expect`. BUN uses `#[expect]` at the site with a reason. CCL: `#[allow]` with a comment. | `#[expect]` with `reason`; `allow` for cfg and macro cases. | Two of three agree and `expect` removes stale suppressions. |
| C-26 | Subject case | GEP: a sentence. Conventional Commits and the kernel: lowercase after the prefix. MEAS: 29 of 100 start lowercase, area names are often capitalized (AOT, WebSocket). | Not enforced; no trailing period is. | Acronyms and proper names make a case rule produce false failures. |
| C-27 | Trailers from bots | MEAS: 15 of 19 squash trailers are the autofix bot. | Not accepted. | Same reason as C-17; fixes are folded into the human's commit. |
| C-28 | Rust enum `#[non_exhaustive]` and public API rules | GRS lists them for libraries; BUN's tree is one binary and denies `unreachable_pub`. | Libraries follow GRS; a workspace that ships one binary may deny `unreachable_pub` as Bun does. | Library rules govern published APIs; a binary has none. |
| C-29 | Unsafe in privileged code | CTP: unsafe in a shipping crate triggers a security review and a `sandbox` group; CUN: no extra approval for first-party. | Privileged crates are reviewed for unsafe (RB-06); first-party unsafe is allowed with comments (RB-05). | The two address different code: dependencies versus our own. |
| C-30 | `unreachable_pub` | KMK warns; BUN denies. | Warn in the template; Bun's tree keeps deny. | Severity follows C-09. |
