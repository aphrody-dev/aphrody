# Kernel watch plan

Hand-written; everything else in this directory is generated by `tooling/kernel-watch`.

## What exists

- `tooling/kernel-watch/sources.toml`: one manifest of every source, host, organisation and satellite site (13 kernels, 62 sources, 19 hosts).
- `cli.ts poll`: conditional (ETag, If-Modified-Since), per-source minimum interval, exponential backoff and Retry-After or rate-limit-reset on 429 and 5xx, bounded per run (`--max-sources`, `--budget`), resumable because all state is in SQLite. Items land in a store with FTS5.
- `cli.ts build`: deterministic views (`versions.md`, `kernels/<id>.md`, `state-of-kernels.md`, `data/*.json`) from the store.
- GitHub Actions workflow `aphrody-kernel-watch.yml`: polls on a schedule, regenerates, commits only when the output changed. The store lives in the Actions cache, never in git.
- Skill `.agents/plugins/aphrody/skills/kernel-watch/SKILL.md` for agents.

## Latency

"Real time" here means minutes. GitHub schedules cron at best every 5 minutes, runs start late under load, and may skip runs. The workflow polls every 5 minutes; the sources set their own minimum intervals (5 minutes for kernel.org releases and the mainline tree, 10 to 30 minutes for forges, hours for slow-moving lists). Version changes are committed at once; activity-only changes at most every 6 hours, so the repository history is not flooded.

## Not done on purpose

- Public site pages: the `aphrody.com` and `aphrody.app` DNS and site roles are frozen until the owner decides them. `data/*.json` and the Markdown pages are what the site will consume; nothing is deployed and no DNS is touched.
- Sub-minute latency: needs webhooks (GitHub and GitLab push events, kernel.org has none) received by a small always-on endpoint that triggers a poll of one source. Design: a Cloudflare Worker validating the signature and calling `workflow_dispatch` with the source id, so the poller stays the single writer.
- Mailing lists: lore.kernel.org is polled through two list feeds only. Full ingestion (public-inbox git clones per list, threading, patch series state) is a separate job for the build host.
- Alpine has no rc kernel (`linux-edge` is absent from aports); Arch's rc is the AUR `linux-mainline`; RHEL is followed through CentOS Stream source-git because RHEL publishes no kernel API.
- Fedora Bodhi is requested with 40 rows; releases older than the newest few can fall outside that page.

## Phase B (build host only)

Blob-less clones of Linux, Asterinas, Redox kernel and LiberNT under `/srv/xbuild/kernel-watch/` on the build host, with a generated structure report per kernel (tree and sizes, subsystem and driver inventory, dependency graph, enforced code style) under `docs/watch/graph/`, each stamped with the commit it was built from. Heavy indexing never runs on a developer machine.
