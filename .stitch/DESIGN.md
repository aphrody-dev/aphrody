# Design System: aphrody.com
**Project ID:** 17049554233938859262

Built from measured first-party references (gemini.google.com computed styles, design.google, Googlebook launch material; see `fw/plugins/aphrody/skills/design/references/google-design.md`) and the Aphrody tokens in `fw/crates/fw-m3/tokens/google_design_tokens.toml`.

## 1. Visual Theme & Atmosphere

Quiet, editorial, engineered. Aphrody's idea is that everything is a file and code is the design material, so the page reads like a well-set technical publication: large calm type, real commands and real file paths as the imagery, generous dark space. Confidence comes from restraint, not ornament. One accent, no gradients on surfaces, no decorative shapes.

## 2. Color Palette & Roles

- **Ink Black (#0F0F0F)** – page background.
- **Graphite (#131314)** – primary surface for bands and panels.
- **Raised Graphite (#1E1F20)** and **High Graphite (#282A2C)** – code blocks and the one elevated panel per section.
- **Soft White (#E3E3E3)** – body text and headlines.
- **Muted Silver (#C4C7C5)** – secondary text and captions.
- **Hairline (#444746)** – 1px dividers and outlines.
- **Gemini Blue (#A8C7FA)** – the only accent: links, the primary button, the active state. Never a fill for large areas.

## 3. Typography Rules

Google Sans Flex throughout; Google Sans Code (monospace) for commands, paths and code. Display sizes are light (weight 280–360) and large; body is 17px at weight 400 with 28px line height; tracking is tight on display sizes (about -2%). Contrast comes from size, not from bold. Plain sentence case; no all-caps labels.

## 4. Component Stylings

* **Buttons:** One primary per screen, fully rounded pill, Gemini Blue fill with Ink Black label; secondary actions are text links in Gemini Blue. No icon-plus-arrow buttons.
* **Cards/Containers:** Avoid card grids. Use full-width bands and at most one panel per section with 28px corners on Raised Graphite, no shadow, no border or a 1px Hairline.
* **Code blocks:** High Graphite, 16px corners, Google Sans Code 15px, real commands only.
* **Inputs/Forms:** None on the home page.

## 5. Layout Principles

1440px canvas, 60px side margins, a 12-column grid with content in a 7-column reading measure and a 5-column side for code or a single image. Sections are full-bleed bands separated by space, not by boxes. Left-aligned text. One idea per section, each led by a short plain headline.

## 6. Design System Notes for Stitch Generation

Pages are generated by `site/build.ts` from workspace data; Stitch output is reference only. Use this block verbatim in every prompt:

```
Code only: each page is one self-contained HTML file with zero runtime requests (no fonts, images, video, icon fonts, CDN scripts). Everything visible is drawn by code: WGSL, inline SVG paths, CSS.
Shell: the site is a Wayland desktop. Wallpaper (wl_output background) after labs.google/projectgenie, drawn by a WebGPU WGSL shader on a full-viewport canvas: black, linear-gradient(290deg, #131722, #5559CF), lit spheres with depth blur that are the workspaces (clickable). Without WebGPU the same gradient and spheres fall back to CSS. Top layer-shell panel: workspaces, live clock, tray links. Bottom layer-shell dock: launchers from freedesktop desktop entries (crates/zed/resources/zed.desktop.in). Pages are workspaces; sections are xdg_toplevel windows with a titlebar (icon, file path, minimize, maximize). One freedesktop-style notification per session (summary, body, 5000 ms expire timeout).
Frame rate and resolution: 120 fps target, 8.3 ms per frame. The canvas backing store is always client size x devicePixelRatio (native resolution, no dynamic downscaling). Frames are rendered only while something moves (spring in flight); an idle page renders nothing. Animate transform and opacity only; backdrop blur only on panel and dock, never on windows.
Layout: Material 3 breakpoints from fw-m3 tokens: compact <600 one pane, margin 16; medium 600-839 one pane, margin 24; expanded 840-1199 and large 1200-1599 two panes; extra-large >=1600 three panes. Maximize and minimize re-tile windows with a FLIP spring.
Content: no prose. Only files, folders, numbers, data and real values read from the repos (paths, sizes in bytes, counts, hex values, versions, commits, commands). The only sentences allowed are the two-line thesis "Everything is a file. / Code is the design material."
Icons: every text item has a Material Symbols Rounded icon, names checked against the official codepoint list at build time; each used icon is inlined once as an SVG <symbol> (outline and filled paths); resting outline, hovered or active filled.
Motion: every action animates with an inline spring integrator using the Material 3 springs from fw-m3 tokens: spatial_default k700 ζ0.9, spatial_fast k1400 ζ0.9, spatial_slow k300 ζ0.9 (parallax), effects_default k1600 ζ1; time-based so motion is identical at 60, 120 or 144 Hz; hover, press, window map, minimize, maximize; prefers-reduced-motion jumps to the end state and stops the wallpaper.
Type: system font stack led by "Google Sans Flex" and "Google Sans Code" when installed locally; nothing downloaded; values tabular.
Color: surfaces from fw-m3 (#131314, #1E1F20, #282A2C) at 92% over the wallpaper, text #E3E3E3, secondary #C4C7C5, line #444746, single accent #A8C7FA.
```
